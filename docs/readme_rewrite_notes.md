### README 안에서 옮긴 것

- 5절 `._*.json` 경고: 원인과 예방 전체가 10절 첫 항목에 있고 5-4 는 명령 한 줄 + 링크.
- 2절 `nvidia-smi` 15GB: 2절에서 설명하고 6-5 진행 상황 보기는 2절을 가리킨다
  (이전에는 양쪽이 각각 설명했다).
- 첫 실행 컴파일: 3-8 에서 설명하고 4절 스모크와 10절 표가 3-8 을 가리킨다.
- 버킷 128 경고: 6-3 경고 블록에 두고 5-2 복합체와 10절 표가 가리킨다.

### 새로 넣은 것

- **5분 요약** (최상단 32행): 이 저장소로 무엇을 하는지, 명령 4줄로 전체 흐름,
  결과를 어떻게 읽는지, 처음이면 어느 절을 읽는지.
- **3-1 다운로드 목록 표**: AF3 소스, 도커 이미지, 가중치(승인 필요, 비영리 한정,
  재배포 금지), ccd.pickle, 축소 DB, 전체 DB, 이 저장소. 각각 용량, 받는 곳, 시간.
  이전에는 1절, 2절, 3절에 흩어져 있었다.
- **8-1 출력 파일 표 강화**: 검증 호스트(gpu-5070ti) `af3out_reduced/vhh_4qgy_1/` 실물을
  읽어 파일별 실제 크기를 적었다. `_data.json` 이 재사용 가능한 입력이라는 것,
  `_model.cif` 의 `B_iso_or_equiv` 열이 원자별 pLDDT 라는 것, 폴더 존재가 완료를 뜻하지
  않는다는 것(AF3 는 추론 전에 `_data.json` 을 쓴다)을 명시했다.
- **8-4 실물 집계 출력**: `af3_collect.py` 를 검증 호스트의 실제 AF3 출력 6건에 돌려
  나온 화면 요약을 그대로 넣었다. CSV 가 35열이라는 것도 실행해 확인했다.
- **5-3 `--dry-run` 실물 출력**: 예제 6종으로 실제 실행해 나온 버킷 분포를 넣었다.

**이 과정에서 README 의 오류 3개를 찾아 고쳤다.**

1. `af3_prepare.py` 사용법이 틀렸다. 이전 README 는 `af3_prepare.py <fasta> --out-dir X`
   로 적었지만 실제 문법은 `--fasta X -o Y` 다. 위치 인자와 `--out-dir` 은 없다.
2. `af3_collect.py --grade-doc` 는 단독으로 못 쓴다. `outputs` 인자가 필수다.
3. `--buckets` 는 `af3_batch.py` 옵션이 아니라 `af3_prepare.py` 옵션이다.
   `af3_batch.py` 는 입력의 토큰 수를 세어 `DEFAULT_BUCKETS`
   (`[128, 256, 384, 512, 768, 1024, ...]`) 에서 쓰이는 버킷만 골라 넘긴다.
   경고 문구를 그에 맞게 고쳤다.

## 4. 9절 3D 대화형 보기

`scripts/af3_view3d.py` 를 만드는 작업이 별도로 진행 중이다. 이 재작성에서는 **9-3 에
자리만 만들고 사용법을 비워 뒀다.** 추측으로 쓰지 않았다. 도구 이름과 목적(pLDDT 로
색칠된 구조를 로컬 브라우저에서 바로 열기)만 적고, 그때까지는 9-2 의 웹 뷰어나
PyMOL/ChimeraX 를 쓰라고 안내한다. 도구가 완성되면 9-3 을 채우면 된다.
